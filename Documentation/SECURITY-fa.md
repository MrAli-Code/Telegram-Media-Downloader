# امنیت — Telegram Downloader

این سند وضعیت امنیتی برنامه را شرح می‌دهد.

## ذخیره‌سازی امن نشست

- نشست تلگرام (سشن Telethon) در فایل `session` داخل `%APPDATA%\TelegramDownloader` ذخیره می‌شود.
- محتوای آن با کلید مشتق‌شده از رمز عبور کاربر و Salt ثابت پروژه رمزنگاری می‌شود (`utils/security.py`).
- نشست هرگز در لاگ‌ها، فایل‌های Crash، یا خروجی Metadata/Export وارد نمی‌شود.

## اعتبارنامه API

- نسخه **Public**: اعتبارنامه را از کاربر می‌گیرد و آن را در **Credential Store** (`credentials.bin`، رمزنگاری‌شده با کلید DPAPI/مشتق‌شده) ذخیره می‌کند.
- نسخه **Personal**: اعتبارنامه به‌صورت Build-Secret (فایل `secrets/personal.env`) در زمان ساخت توسط `scripts/generate_build_info.py` تزریق می‌شود. این فایل در `.gitignore` است و در مخزن عمومی قرار نمی‌گیرد.
- `config/_build_info.py` (خروجی Build) از سورس کنترلی حذف شده (در `.gitignore`).

## کلیدها و مشتق‌سازی

- رمزنگاری نشست و اعتبارنامه با KDF (PBKDF2-HMAC-SHA256 و تأخیر مناسب) انجام می‌شود، نه نگه‌داری رمز به‌صورت خام.
- پشتیبانی از DPAPI ویندوز برای حفاظت از کلیدهای محلی وجود دارد.

## داده‌های حساس

- فایل‌های دانلودشده به‌صورت کامل **ابتدا `*.part`** نوشته می‌شوند و پس از پایان موفق و تأیید SHA-256 به نام نهایی تغییر می‌یابند؛ فایل ناقص به‌عنوان فایل سالم نمایش داده نمی‌شود.
- خروجی Metadata (JSON/CSV) شامل اعتبارنامه، نشست یا محتوای پیام خصوصی نیست.

## Audit انجام‌شده (قبل از Release)

- [x] جستجوی Secret/کلید در سورس؛ هیچ اعتبارنامه‌ای خارج از `secrets/` و `config/_build_info.py` (هر دو gitignore) یافت نشد.
- [x] `secrets/personal.env` به سورس راه ندارد؛ فقط در زمان Build خوانده می‌شود.
- [x] لاگ‌ها و دیتابیس از سورس کنترل خارج‌اند (`*.log`، `data/` در gitignore).
- [x] نصب‌کننده: انصراف‌پذیر + سؤال حذف داده‌ها (Clean Uninstall).
- [x] Feature Flags برای ماژول‌های اختیاری (Backup/Encryption/Streaming)؛ غیرفعال بودنشان پایدار است.

## محدودیت‌های شناخته‌شده

- امضای Authenticode (کد توشه) و SmartScreen انجام نشده است؛ نصب‌کننده با هشدار SmartScreen مواجه می‌شود.
- Auto-Lock (App Lock) و رمزنگاری کامل آپلود هنوز فعال نیستند (در رده P2 با Feature Flag غیرفعال).
